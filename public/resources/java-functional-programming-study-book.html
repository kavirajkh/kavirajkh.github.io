⚡ Functional Java: 12 things to remember
  1. A lambda needs a functional interface target type; the compiler infers everything else.
  2. Captured locals must be effectively final; never mutate outside state from a lambda.
  3. A stream is lazy and single-use: nothing runs without a terminal operation.
  4. map is 1-to-1, flatMap flattens; reduce combines, collect builds containers.
  5. toMap needs a merge function when keys can repeat.
  6. orElse is eager, orElseGet is lazy; never call Optional.get() blindly.
  7. Optional is for return types, not fields or parameters.
  8. Build comparators with comparing().thenComparing(); never subtract ints.
  9. Parallel streams only for large, CPU-bound, stateless work; measure first.
  10. Prefer immutability: records, List.of, Stream.toList().
  11. Sealed types plus pattern switch (21) give exhaustive, compiler-checked branching.
  12. Use virtual threads (21) for blocking I/O; use CompletableFuture to compose async results.

1 · Functional mindset

Think in “data in → data out” instead of “loops mutating variables”.

⚡ At a glance
  • What: style built on pure functions, immutable data and declarative pipelines.
  • Must know: first-class and higher-order functions are lambdas typed as functional interfaces.
  • Must know: prefer creating new objects (records, List.of, toList()) over mutating.
  • Pitfall: forcing FP everywhere; a plain loop is fine for index-heavy or stateful early-exit logic.
  • Version: Java 8 introduced the style; later versions only add sugar.
Pure functionSame input → same output, no side effects. Easy to test, safe in parallel.
First-class functionA function can be stored in a variable, passed in, returned. In Java: lambdas typed as functional interfaces.
Higher-order functionTakes or returns a function: map, filter, Comparator.comparing.
ImmutabilityDo not change objects, create new ones: records, List.of, toList().
DeclarativeSay what you want (filter, map, group), not how (index, temp list, if).

Imperative vs declarative

🧠 RememberFunctional Java = pure functions + immutable data + pipelines. If a lambda changes something outside itself, you are probably fighting the style.
⚠ PitfallJava is not Haskell. Use FP where it makes code shorter and safer (collections, Optional, async); a plain for loop is still right for index-heavy or early-exit-with-state logic.

2 · Lambda expressions

A lambda is an inline implementation of a functional interface’s single method.

⚡ At a glance
  • What: (args) -> body, valid only where a functional interface is expected.
  • Must know: the compiler infers the interface from the target type; a lambda has no type of its own.
  • Must know: this inside a lambda is the enclosing class, unlike an anonymous class.
  • Pitfall: captured locals must be effectively final; do not mutate outside state.
  • Version: Java 8; var in lambda parameters since 11; unnamed _ parameter since 22.
🔑 Key ideaThe compiler infers which interface from the target type (assignment, method parameter, return type). A lambda has no type of its own.
💡 Tip: lambda or anonymous class?Lambda: this = enclosing class, no new scope, compiled with invokedynamic (no extra .class file). Anonymous class: this = the anonymous object, can have state and multiple methods.
⚠ Pitfall: captured variables must be effectively finalA lambda can read local variables only if they are never reassigned. Use a field, AtomicInteger, or (better) a stream operation like count().

How are lambdas implemented by the JVM? Is a lambda “just an anonymous inner class”?
Answer

No. javac emits a private synthetic method for the lambda body and an invokedynamic call site. At first execution, LambdaMetafactory spins up the functional-interface implementation at runtime. What exactly makes an interface “functional”? Is Comparator one, given it declares equals? Is @FunctionalInterface required?
Answer

Exactly one abstract method. default, static and private methods do not count, nor do abstract methods that match public methods of Object (equals). So Comparator is functional (compare is its only real abstract method). The annotation is optional; it just makes the compiler reject a second abstract method — add it to your own interfaces for safety.

4 · Method references

A method reference is a lambda that just calls an existing method: shorter and named.

⚡ At a glance
  • What: Type::method shorthand for a lambda that just forwards its arguments.
  • Must know: static Integer::parseInt, bound list::add, unbound String::length, constructor Person::new.
  • Must know: array constructors work too: int[]::new.
  • Pitfall: overloaded methods can be ambiguous; fall back to an explicit lambda.
  • Version: Java 8.

5 · Composing functions

Build big behaviours from small ones: andThen, compose, and/or/negate, currying.

⚡ At a glance
  • What: combine small functions and predicates into bigger ones.
  • Must know: f.andThen(g) = g(f(x)); f.compose(g) = f(g(x)).
  • Must know: Predicates chain with and, or, negate; use Predicate.not(String::isBlank).
  • Pitfall: mixing up andThen and compose order.
  • Version: Java 8; Predicate.not since 11.
💡 TipName your predicates (isActive, isOverdue) as constants or static methods in the domain class, then combine them. Business rules become readable: filter(isActive.and(isOverdue.negate())).

6 · Stream pipeline fundamentals

A stream is a lazy, single-use pipeline: source → intermediate operations → one terminal operation.

⚡ At a glance
  • What: lazy pipeline over a source (collection, array, Stream.of, iterate, generate).
  • Must know: intermediate operations are lazy; the terminal operation triggers work.
  • Must know: elements flow one by one through the whole pipeline (vertical processing), enabling short-circuiting.
  • Pitfall: reusing a stream throws IllegalStateException.
  • Version: Java 8; Stream.toList() 16.

  • Must know: sorted and distinct are stateful and buffer elements.

How do ScopedValues differ from ThreadLocal, and why do they suit virtual threads?
Answer

ThreadLocal is mutable, lives until removed (leaks on pooled threads) and every virtual thread copying inherited values is costly with millions of threads. A ScopedValue is immutable, bound for a bounded dynamic scope (where(...).run(...)), automatically unbound afterwards, and is shared cheaply with child tasks created in StructuredTaskScope. Use cases: tenant id, correlation id, authenticated principal passed implicitly down a call tree.

Explain exceptionally, handle and whenComplete. Which can change the result?
Answer

exceptionally(ex -> fallback): runs only on failure and supplies a replacement value. handle((value, ex) -> result): runs always, can return a new value (success or recovery). whenComplete((value, ex) -> …): runs always but only observes (logging, cleanup); the original result or exception is propagated unchanged. So exceptionally and handle can change the outcome; whenComplete cannot.

What is the risk of calling CompletableFuture.supplyAsync(() -> restClient.get(...)) without an executor inside a Spring service?
Answer

It runs on ForkJoinPool.commonPool() (also used by parallel streams), with only cores − 1 threads (on a 2-CPU container that is 1 thread, or a plain thread-per-task fallback). Blocking calls exhaust it and unrelated async work stalls. Pass a bounded Executor bean (ThreadPoolTaskExecutor) or a virtual-thread executor; set timeouts with orTimeout.

When do virtual threads help, when not? Mention pinning and how to enable them in Spring Boot.
Answer

They help with blocking I/O concurrency (HTTP, JDBC, messaging): thousands of concurrent requests with simple synchronous code. They do not speed up CPU-bound work and are not to be pooled. Pinning: in Java 21–23 a virtual thread blocked inside synchronized (or native code) pins its carrier thread, reducing scalability; Java 24 removes the synchronized case. Also limit downstream concurrency with a Semaphore (DB pool size is still finite). Enable in Boot 3.2+: spring.threads.virtual.enabled=true.

Reactive vs streams: how is a Reactor Flux different from a java.util.stream.Stream, and what do map/flatMap mean there?
Answer

A Stream is a synchronous, pull-based, single-use pipeline over data you can iterate. A Flux/Mono is an asynchronous, push-based, back-pressured publisher: nothing happens until someone subscribes, values may arrive over time, and errors/completion are signals. map transforms an element synchronously; flatMap takes a function returning a Publisher (e.g. an async HTTP call) and merges the inner results (possibly out of order). Same vocabulary, different execution model; with virtual threads many teams stay on blocking MVC + streams for simplicity.
